# P0-F — Technical Cleanup: 36 & 38

## Mission

Implement only:

* **36 — Codebase Cleanup / Consolidation**
* **38 — Standard Demo / Seed Data**

Do not redesign business architecture or implement P0-A/B/C/D/E.

Use the existing Polaris repository and current schema as the source of truth. Do not invent Product/SKU/Supplier/Warehouse tables if they do not yet exist.

---

# STEP 1 — Inspect Before Editing

1. Inspect:

   * root `package.json`
   * `backend/package.json`
   * `.gitignore`
   * `frontend/.gitignore`
   * `backend/scripts/*`
   * `backend/drizzle/*`
   * `backend/src/routes/*`
   * `frontend/src/*`
2. Identify:

   * temporary/generated files
   * duplicate source files
   * duplicate routes
   * broken imports
   * broken scripts
   * migration inconsistencies
   * existing Seed scripts
3. Do not delete or consolidate legitimate compatibility modules merely because names look duplicated.
4. Preserve existing business behavior.

# STEP 2 — Remove Temporary Artifact

Delete:

```text
frontend/.tmp-dp.js
```

Do not replace it with another generated JS artifact.

Ensure temporary/build files are ignored by Git.

---

# STEP 3 — Add Codebase Audit

Create:

```text
backend/scripts/codebase-audit.mjs
```

The script must be **read-only** and must check:

1. forbidden temporary/generated artifacts
2. broken relative imports
3. broken `@/` imports
4. duplicate HTTP routes within the same router
5. migration numbering continuity
6. migration journal ↔ migration-file consistency
7. missing migration snapshots as warnings only
8. broken root test script
9. exact duplicate source files as warnings
10. workshop route mount consistency

Exit:

```text
0 = no errors
1 = one or more errors
```

Never modify source files or database data.

---

# STEP 8 — Demo Seed Safety Requirements

The demo seed must:

1. require:

```text
POLARIS_DEMO_SEED=true
```

2. fail safely if that flag is absent
3. use deterministic IDs
4. be idempotent
5. never overwrite real records
6. never delete real records
7. mark demo records clearly with:

```text
DEMO-
```

8. use the current database schema
9. fail clearly when required tables are missing
10. never fabricate tables that belong to later P0 phases.

---

# STEP 9 — Seed Current Existing Domains

Using only tables that currently exist, seed representative data for:

* categories
* items/products represented by current `items`
* sellers
* consignments
* consignment returns
* payments
* staff
* expenses
* damage records
* workshop todos
* orders

The demo dataset must contain enough variation to test:

* normal stock
* multiple sizes
* multiple colors
* low-stock behavior
* seller handover
* partial sales
* return
* partial settlement
* remaining seller debt
* staff activity
* expense records
* damaged inventory
* pending task
* customer order

Use realistic but obviously synthetic Persian data.

Never use real credentials, tokens, customer information, bank information, or secrets.

# STEP 14 — Migration Safety

Do not fabricate missing migration snapshots.

If audit detects historical snapshot inconsistencies:

* report them
* classify them
* do not silently rewrite migration history
* do not renumber existing migrations
* do not delete migrations

Migration-history correction belongs to P0-B / item 37 unless explicitly requested.
